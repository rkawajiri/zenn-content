title: "用語集"
---

この本に出てくる用語を、frePPLe での使われ方に合わせて短くまとめます。英語の表記は、画面や API で見えるものです。

## 計画の基本

| 用語 | 意味 |
|---|---|
| MRP（所要量計算） | 受注（需要）から、必要な部品・製造・購買の量とタイミングを逆算する計算。能力の上限は考えないのが基本です。「制約なし計画」は、これに近い計画です |
| 制約なし計画 / 制約あり計画 | 制約なし（Unconstrained）は「すべての受注を納期どおりに」を最優先し、能力オーバーや過去日付のオーダーを許して、問題として警告します。制約あり（Constrained）は制約を守り、守れない分を受注の遅れや不足として表します |
| 有限能力 | 設備や人の能力に上限がある、という前提。「制約あり計画」で Capacity 制約をオンにすると、これを守ります |
| 計画基準日（currentdate） | 計画の「今日」にあたる日。frePPLe のパラメータで、デモデータでは `today`（実行日）です。これより前の日付にはオーダーを置かないのがリードタイム制約です |
| リードタイム | 発注してから届くまで、着手してから終わるまでにかかる時間。調達リードタイム（Purchasing）と製造リードタイム（Manufacturing）があります |
| 優先度（priority） | 資源や部品が足りないとき、どの受注に先に割り当てるかの順位。frePPLe では **数字が小さいほど高い** です（既定値は 10） |
| ヒューリスティック | 厳密に最適解を探すのではなく、経験則に基づく手順で手早くよい解を作る方法。frePPLe の計画エンジンは、受注を優先度順に 1 件ずつ計画する方式です |

## モデルの要素

| 用語 | 意味 |
|---|---|
| 品目（item） | 作る・買う・売るもの |
| 拠点（location） | 工場・倉庫・店舗など、品目や設備がある場所 |
| バッファ（buffer） | 品目 × 拠点の在庫の単位。在庫の入出庫が積み上がる場所です |
| 部品表（BOM） | 1 つの製品を作るのに必要な材料と数量。frePPLe では、工程に対する operation material（消費は負の数）で表します |
| 工程（operation） | 材料を消費し、時間をかけ、設備を使って、品目を作る活動 |
| リソース（resource） | 設備や人。同時に扱える量（maximum）で能力を表します |
| サプライヤー / 品目×サプライヤー | 購買先と、どの品目をどの条件（リードタイムなど）で買えるか |
| 受注（demand / sales order） | 顧客からの需要。納期（due）、数量、優先度を持ちます |
| 補充手段 | 品目を増やす方法。買う（buy）、運ぶ（transfer）、作る（make）の 3 種類です |

## 計画の結果

| 用語 | 意味 |
|---|---|
| 製造オーダー（MO） | 何を、いつからいつまで、いくつ作るかの指示 |
| 購買オーダー（PO） | 何を、どのサプライヤーから、いつ、いくつ買うかの指示 |
| 配送オーダー（DO） | 拠点間で何をいつ運ぶかの指示 |
| 納品（DLVR） | 受注ごとの出荷 |
| オーダーの status | `proposed`（計画エンジンの提案。再計画のたびに作り直される）、`approved`（承認済み。制約に違反すると動かされる）、`confirmed`（確定。frePPLe は動かせない）、`completed`（実行済み）、`closed`（完了済みで計画からは無視） |
| ペギング | 供給（オーダー）が、どの受注のために作られているかの紐づけ |
| 供給経路（supply path） | ある品目が、どこから、どの工程を通って供給されるか |

## 結果の読み方

| 用語 | 意味 |
|---|---|
| 問題（problem） | 計画上の警告。能力オーバー（overload）、部品不足（material shortage）など |
| 制約レポート（constraint report） | 受注が遅れた・不足した理由を、制約の種類別に示すレポート |
| ボトルネック | 全体の進み方を決めている、もっとも余裕のない資源。制約レポートで overload が集中するリソースがその候補です |
| 負荷率（utilization） | 使用可能な能力に対する、実際の使用量の割合。100% を超えると能力オーバーです |
| フェンス（fence） | 計画基準日から先の一定期間。この間は新しい補充を提案しないための「凍結期間」です |

## 比較と最適化

| 用語 | 意味 |
|---|---|
| What-if | 「もし〜だったら」を試すこと。frePPLe ではデータベースを丸ごとコピーした **シナリオ** の中で行います |
| ジョブショップ | 限られた機械に、複数の仕事の順序を決めて割り当てる問題の型 |
| CP-SAT | Google OR-Tools の制約プログラミングソルバー。変数・制約・目的関数を宣言すると、条件を満たす最良の解を探します |
| NoOverlap（重なり禁止） | 同じ資源の上で、2 つの仕事の時間が重ならないという制約。11 章のモデルで使います |
| 遅れ（tardiness） | 納期（この本では元の終了日）を超えた分の時間。11 章の目的関数は、この合計を最小にすることです |
